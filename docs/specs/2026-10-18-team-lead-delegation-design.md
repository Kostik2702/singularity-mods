## 1. Цель

Владелец говорит только с лидом — главной сессией на Opus. Лид сам решает, что делать самому, а что отдать исполнителю, и на какой модели и с каким effort его запустить; проверяет результат. Цель — **экономия токенов** (лимитов подписки) без потери качества там, где нужно думать.

Главные источники выжигания лимитов, со слов владельца:
1. dynamic workflows, агенты которых наследуют модель лида (Opus→Opus, Fable→Fable);
2. большие процессы чтения, записи, генерации в контексте лида.

**Критерий успеха:**
- агент workflow или субагент, которому модель не указали, никогда не получает Opus/Fable молча;
- Fable за сессию вызывается только советчиком, с записанным обоснованием, не чаще лимита; council не стартует без команды владельца;
- при исчерпании бюджета сессии исполнители не делают ни одного нового запроса к модели, а лид останавливается и спрашивает владельца;
- зависший исполнитель замечен и лиду об этом сказано, даже если лид простаивает;
- лид в любой момент знает, кто из исполнителей чем занят, сколько потратил и сколько осталось, не перечитывая полные отчёты;
- после недели режима наблюдения есть реальные цифры расхода по ярусам, из которых ставятся лимиты.

Факты из документации Claude Code (проверено 2026-10-18; [sub-agents](https://code.claude.com/docs/en/sub-agents), [workflows](https://code.claude.com/docs/en/workflows), [advisor](https://code.claude.com/docs/en/advisor), [costs](https://code.claude.com/docs/en/costs)):

| Факт | Следствие |
|---|---|
| Модель субагента: (1) параметр `model` вызова → (2) `model:` во frontmatter (`inherit` = модель лида) → (3) `CLAUDE_CODE_SUBAGENT_MODEL` → (4) модель лида. Модель, выставленная хуком `agent.spawn` мода, заменяет параметр вызова. `CLAUDE_CODE_SUBAGENT_MODEL_FORCE=1` перекрывает всё | модель по умолчанию задаётся переменной, мод её не пишет; `_FORCE` не включать — он отнимает у лида выбор |
| Агенты workflow выбирают модель в том же порядке; модель, указанная скриптом, = параметр вызова | переменная покрывает и workflow |
| `effort` вызова (v2.1.292+) перекрывает frontmatter и сохраняется при возобновлении; `CLAUDE_CODE_EFFORT_LEVEL` перекрывает оба | переменную `CLAUDE_CODE_EFFORT_LEVEL` не ставить (сейчас не задана; `effortLevel: high` в settings — уровень сессии, не переменная) |
| `maxTurns`: по достижении вывод возвращается помеченным как частичный, агент можно возобновить | лимит ходов не теряет работу |
| Потолки: 20 одновременных субагентов (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`), вложенность 3 (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`), 16 одновременных агентов workflow (`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`), 1000 агентов на прогон | потолки разветвления — настройками |
| `workflowSizeGuideline`: `small` < 5 агентов, `medium` < 10 (по умолчанию), `large` < 50 — совет модели, не лимит; предупреждение `Large workflow` при > 25 агентов или > 1.5M токенов | ставим `small` |
| Агент без вывода дольше окна простоя перезапускается автоматически, до 5 раз (`stallMs` у `agent()`, `CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS` — и для субагентов вне workflow). Время ожидания собственных вызовов инструментов в окно не входит | «молчащий» агент движок лечит сам; мод следит за долгими вызовами и сообщает лиду |
| Запросы разрешений фоновых субагентов показываются в главной сессии с именем агента | фоновый исполнитель не упирается молча в отказ (прежний риск снят) |
| Агенты workflow с одинаковыми моделью, effort, типом, инструментами, схемой и каталогом делят кеш префикса; кеш агента workflow живёт 5 мин (`subagentPromptCacheTtl`) | effort по ярусу в прогоне — единый, иначе кеш не делится |
| `omitClaudeMd: true` во frontmatter — агент не грузит CLAUDE.md пользователя, проекта и локальный | крупная экономия на каждом запуске исполнителя |
| Встроенный советчик: при Opus 5.5 принимает Fable или Opus 5+; видит весь разговор; чтение разговора советчиком не кешируется; «There is no setting to cap or force advisor calls»; субагенты наследуют настроенного советчика | D15 |

Опыт Anthropic ([multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system)): правила масштаба записаны прямо в промпт лида (простое — 1 агент и 3–10 вызовов; сравнение — 2–4 агента по 10–15 вызовов; сложное — больше 10 агентов с разделёнными зонами); ранние версии запускали 50 агентов на простой вопрос и продолжали искать после достаточного результата; задание = цель, формат вывода, инструменты и источники, границы; большие результаты агенты кладут во внешнее хранилище и возвращают лёгкую ссылку; качество оценивали примерно на 20 реальных задачах одним LLM-судьёй с рубрикой.

Цены (skill `claude-api`, таблица 2026-10-06), $ за 1M токенов, вход / выход / чтение кеша: Opus 5.5 — 4 / 20 / 0.20; Sonnet 5.5 — 2 / 10 / 0.20; Haiku 5.5 — 0.10 / 0.50 / —; Fable 5.1 — 10 / 50 / 0.25. **Sonnet дешевле Opus лишь вдвое, чтение кеша — столько же.** Основная экономия — Haiku и разгрузка контекста лида.

Почему не отдельные сессии (D2): у сессии модель фиксируется при старте, `maxTurns` не задать, лид её не остановит, у каждой свой экземпляр мода (общий бюджет — только через файл), результат приходит сообщением, а не отчётом.

## 4. Архитектура

```
владелец ⇄ ЛИД (главная сессия, Opus)
              │ рубрика (скил team-lead, часть A) — решает: сам / кому / модель / effort
              ▼
        Agent / Workflow agent()
              │
   ┌──────────┴──────────────── mission-control (часть B) ─────────────────┐
   │ agent.spawn guard: Fable, council, модель по умолчанию, бюджет спавна  │
   │ turn.step guard:   бюджет до запроса, заморозка, учёт usage            │
   │ watchdog:          тишина, долгий вызов → тревога → сводка / пробуждение│
   │ digest:            изменения → additionalContext лиду                  │
   │ ledger:            OE по агенту / прогону / сессии; журнал недели       │
   └────────────────────────────────────────────────────────────────────────┘
              ▼
   scout (Haiku) · coder (Sonnet) · reviewer/critic… (Opus) · advisor (Fable)
```

Граница: **мод не выбирает ярус за лида** (это суждение). Дешёвую модель там, где лид её не указал, подставляет сам Claude Code (`CLAUDE_CODE_SUBAGENT_MODEL`, часть 0). Мод не пускает то, что запрещено решениями D4, D9, D10, и считает расход.

## 5.0 Часть 0 — настройки Claude Code (`~/.claude/settings.json`)

| Ключ | Значение | Что даёт |
|---|---|---|
| `env.CLAUDE_CODE_SUBAGENT_MODEL` | `sonnet` | субагент или агент workflow без модели (ни вызов, ни скрипт, ни frontmatter) работает на Sonnet, а не на модели лида |
| `workflowSizeGuideline` | `small` | лид пишет workflow меньше чем на 5 агентов, если задача не требует иного |
| `env.CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS` | `8` | не больше 8 одновременных субагентов (*моё значение, ASSUMED*) |
| `env.CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` | `2` | исполнитель может позвать помощника, помощник — уже нет (*ASSUMED*) |
| `advisorModel` | не задавать | D15 |
| `env.CLAUDE_CODE_SUBAGENT_MODEL_FORCE`, `env.CLAUDE_CODE_EFFORT_LEVEL` | не задавать | иначе выбор лида игнорируется |

## 5. Часть A — движок Singularity

### 5.1 Скил `team-lead` (`singularity/skills/team-lead/SKILL.md`)

Рубрика лида. Содержимое:

1. **Право выбирать модель и effort исполнителю** — прямым текстом. Канал — параметры `model` и `effort` инструмента Agent (они есть в схеме инструмента у лида; в типах мода `AgentSpawnInput` поля `effort` нет — хук его не видит и не переписывает). Описание параметра `effort` в схеме инструмента разрешает ставить его «only when the user, or instructions such as CLAUDE.md or a skill, explicitly ask» — поэтому без этой строки в скиле лид effort ставить не будет.
2. **Делать самому, а не делегировать**, когда: точечная правка, содержимое которой лид уже знает (задание стоило бы столько же, сколько правка); нужен точный текст файла для собственной правки; задача меньше, чем её описание.
3. **Таблица ярусов** (стартовая, правится по данным недели наблюдения):

   | Работа | Агент | Модель · effort |
   |---|---|---|
   | поиск, чтение с выжимкой, разбор логов, инвентаризация | `scout` | haiku · low |
   | массовые однотипные правки по точному шаблону | `coder` | haiku · low |
   | код и тесты по объяснённому плану | `coder` | sonnet · medium |
   | рефакторинг, сложный код по плану | `coder` | sonnet · high |
   | прогоны, замеры, сбор данных внутри исследования | `scout`/`coder` | haiku/sonnet · low/medium |
   | проверка результата, ревью, критика, валидация | `reviewer`/`critic`/`validator` | opus · high |
   | совет по самому важному и сложному вопросу | `advisor` | fable (effort не ставится — §5.2) |

4. **Масштаб** (по опыту Anthropic, §3): простое — сам или 1 исполнитель; сравнение или несколько независимых частей — 2–4 исполнителя; workflow — только когда частей больше, чем можно удержать, и не больше 5 агентов без причины (`workflowSizeGuideline: small`). Не запускать исполнителя на вопрос, ответ на который уже есть в контексте.
5. **Шаблон задания** исполнителю: цель; файлы и точки; критерий готовности **и критерий остановки** («нашёл достаточно — остановись»); формат вывода; что вне задачи; **большой результат (код, таблица, отчёт длиннее ~40 строк) — в файл, лиду — путь и выжимка**; «вопросы бизнес-логики, необратимые действия, развилки — не решай, верни лиду»; «выводы с цитатами `file:line`, не пересказом»; строка `ярус · effort · почему` в `description` спавна.
6. **Приёмка**: лид проверяет по критерию готовности; замечание отправляет **тому же** исполнителю (`SendMessage` по `agentId`), не новому.
7. **Исполнители — в фоне** (`run_in_background`): лид не простаивает в ожидании, а сторож может разбудить его тревогой (§6.5).
8. **Fable**: только `advisor`, только с полем `ПОЧЕМУ FABLE:` в задании (что решается, почему Opus не справится, цена ошибки), один вопрос, короткий ответ. Не в workflow, не в council. Встроенный `/advisor` не включать (D15).
9. **Council** — только по команде владельца. Нужен council → лид просит владельца вызвать его и объясняет зачем.
10. **Workflow-скрипты**: у агентов механики модель можно не указывать (её даст `CLAUDE_CODE_SUBAGENT_MODEL`); Opus — явно и только для проверяющих агентов; Fable — никогда; у однотипных агентов прогона одинаковые модель, effort и тип (общий кеш префикса); форки — не для механики (их модель не удешевить).
11. **Бюджет**: при сообщении мода «бюджет сессии исчерпан» — остановиться и спросить владельца (`AskUserQuestion`: добавить бюджет / закончить самому / остановить всё). При «80 %» — сказать владельцу одной строкой.

### 5.2 Агенты (`singularity/agents/`)

Новые:
- **`scout`** — `model: haiku`, `effort: low`, `maxTurns: 30`, `omitClaudeMd: true` (D16), `background: true`, инструменты только чтения (`Read`, `Grep`, `Glob`, `Bash` для чтения). Возвращает выжимку с цитатами `file:line`; длинный результат — в файл, лиду путь.
- **`advisor`** — `model: fable`, `maxTurns: 8`, инструменты только чтения. Один вопрос → один короткий ответ с рекомендацией и уверенностью. `effort` не задаётся: у Fable thinking всегда включён, глубину лид задаёт вопросом.

Существующие получают `model:` по умолчанию — на случай, когда лид модель не указал (*моё решение, ASSUMED*): `coder`, `web-implementer` → sonnet; `historian` → sonnet; `investigator`, `critic`, `validator`, `reviewer`, `web-viewer` → opus. `maxTurns` для существующих — после недели наблюдения.

Во всех агентах (через `AGENT_SHARED_PREAMBLE.md` §2 — одна точка для всех): «вопросы бизнес-логики, необратимые действия, развилки — не решай, верни лиду».

## 6. Часть B — `mission-control`

Новая фича `hooks/lead/` рядом с `memory/`, `mission/`, `jobs/`; подключается из `register.tsx`. Чистая логика (учёт, правила, сводка) — в чистых функциях, как `mission/model.ts`.

### 6.1 Настройки (`plugin.json` → `userConfig`)

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `budgetMode` | `observe` | `observe` — считать и показывать; `enforce` — блокировать по числам |
| `sessionBudgetOE` | пусто | бюджет сессии в OE; пусто — без лимита |
| `runBudgetOE` | пусто | бюджет одного прогона workflow |
| `agentBudgetOE` | пусто | бюджет одного исполнителя |
| `fableCap` | 3 | вызовов `advisor` за сессию (действует и в `observe`: D4 не зависит от чисел) |
Константы (не настройки, до данных недели наблюдения): порог «нет вестей» 15 мин для любого яруса (короткое молчание движок лечит сам перезапуском, §3); порог одного вызова инструмента 20 мин.

### 6.2 Учёт (ledger)

- Источник — `usage` в результате каждого `turn.step` (модель берётся из `usage`, не из запроса).
- **OE** (Opus-эквивалент) = Σ по видам токенов (вход, выход, запись кеша, чтение кеша) `токены × цена(модель, вид) / цена(Opus 5.5, вход)`. Таблица цен — константа в коде с датой источника; модель, которой нет в таблице, считается по цене Fable и помечается в сводке.
- Копится по агенту, по `workflow.runId`, по сессии; лид считается в сессию.
- Журнал недели: по концу каждого исполнителя одна строка JSON (`ярус · effort · subagentType · ходы · OE · длительность · исход`) в файл вне репозитория (путь — на усмотрение исполнителя плана, в каталоге данных плагина). Из него ставятся числа для `enforce`.

### 6.3 Ограждение спавна (`agent.spawn`)

Порядок проверок:
1. **Council.** Промпт содержит `COUNCIL MISSION`, а текущий ход главного начат не командой `council` / `planning-council` / `observation-council` → `deny`: «Council запускается только командой владельца — попроси его». Внутри окна council: модель Fable или не указана → `opus`.
2. **Fable.** Модель (алиас или id) — Fable:
   - в workflow → переписать на `opus`, строка в сводку;
   - `subagentType` не `advisor`, или в промпте нет непустого `ПОЧЕМУ FABLE:`, или исчерпан `fableCap` → `deny` с причиной.
3. **Модель по умолчанию** — не дело мода: её даёт `CLAUDE_CODE_SUBAGENT_MODEL` (часть 0). Мод только показывает фактическую модель (из `usage.model` первого запроса) на карточке и в сводке.
4. **Бюджет** (только `enforce`): бюджет сессии, прогона исчерпан или заморозка (§6.6) → `deny`: «бюджет исчерпан — остановись и спроси владельца».
5. **Форк** — не переписывается; учитывается и помечается в сводке «форк · модель лида».

### 6.4 Ограждение запроса (`turn.step`)

- Для субагента в `enforce`: бюджет агента, прогона или сессии исчерпан, или заморозка → ответ без `next` (запрос не уходит): `answer` = «[mission-control] остановлен до запроса: бюджет исчерпан / заморожено владельцем», без `toolUses`. Ход исполнителя кончается, лид получает это как отчёт. Текущий запрос не обрывается — превысить бюджет может только он.
- Для лида запросы **не** блокируются (иначе лид не сможет спросить владельца — D10). При исчерпании бюджета сессии лиду уходит сводка «бюджет сессии исчерпан: потрачено X OE, по агентам …», и рубрика велит остановиться и спросить.
- Сессия, запущенная на Fable как лид → один раз тост и строка в сводке: «лид на Fable — всё без явной модели унаследует Fable».

### 6.5 Сторож

- Короткое молчание (нет вывода модели) движок лечит сам: перезапуск агента до 5 раз (§3). Мод это не дублирует.
- Тишина: работающий субагент без событий дольше 15 мин → тревога «нет вестей N мин» (агент, который движок уже не спас).
- Долгий вызов: один вызов инструмента дольше 20 мин → тревога. Это главный случай сторожа: время ожидания собственных вызовов в окно простоя движка не входит.
- Тревога идёт в сводку (§6.6). Если лид простаивает (нет идущего хода главного) — `$.prompt.submit` с короткой строкой тревоги; не чаще одного раза на агента на тревогу.
- Мод агента не убивает. Решение — за лидом: `TaskStop`, `SendMessage` с вопросом или ждать.

### 6.6 Сводка лиду и вмешательство владельца

- **Push**: классический `PostToolBatch` главного (без `agentId`) → `additionalContext`, **только изменения** с прошлой сводки: запущен (ярус · effort · задача), закончил (исход · OE), нет вестей, долгий вызов, 80 % бюджета, отказ в спавне, переписанная модель. Нет изменений — нет текста. Потолок 600 символов, однотипные строки сливаются. Те же изменения — в `context` очередного промпта владельца.
- **Pull**: новый MCP-инструмент `mcp__mission-control__team` — компактная таблица: агент · ярус · effort · задача · ходы · OE / лимит · состояние. Существующий `snapshot` не трогается.
- **Вкладка «Агенты»**: на карточке — модель · effort · OE (и лимит в `enforce`); в шапке — бюджет сессии и режим (`наблюдение` / `контроль`); отказы и переписанные модели — в ленту.
- **Команды** (в `/mc`): `/mc budget` — расход и лимиты; `/mc budget +N` — добавить N OE к бюджету сессии; `/mc halt` — заморозить исполнителей (§6.4) и сказать лиду «остановлено владельцем»; `/mc resume` — снять заморозку; `/mc solo` — строка лиду «дальше делай сам, не делегируй».

### 6.7 Краевые случаи (уточнено после проверки спека; решения — *мои, ASSUMED*)

- **Effort у агентов workflow.** Если `agent()` не принимает `effort` — мод ставит его в `turn.step` этого агента по ярусу модели (haiku → low, sonnet → medium, opus → high; Fable не трогается). Агентам, запущенным через Agent, effort не переписывается — это выбор лида.
- **Промпт агента workflow может быть заглушкой** (прогон, скрывающий скрипт от событий; переписывание промпта тогда не применяется). Поэтому для workflow не полагаемся на текст промпта: Fable в workflow всегда → `opus`; council внутри workflow детерминированно не ловится — только правило рубрики, вне объёма.
- **Видимость агентов workflow.** `$.agent.list()` их не содержит, но `turn.step` и `turn.complete` несут их `agentId`, и `mission-control` уже отслеживает их по событиям (вкладка «Агенты» показывает агентов workflow). Сторож и учёт идут по тем же событиям, не по `list()`.
- **«Лид простаивает»** = последнее событие главного — `turn.complete`, нового `turn.start` главного не было (то же состояние, что вкладка рисует «ждёт тебя»). Пробуждение `$.prompt.submit` — это ход лида на Opus, поэтому не чаще одного на агента на тревогу **и** не чаще одного за 10 минут на сессию.
- **Форк** в `enforce` при исчерпанном бюджете сессии/прогона — `deny`, как любой спавн. **Возобновление** (`resume`) переписать нельзя, только отказать: в `enforce` при исчерпанном бюджете — `deny`.
- **Лид на Fable** — модель главного мод не меняет (это выбор владельца при старте): тост и строка в сводке. Спавны без модели всё равно получают Sonnet: `CLAUDE_CODE_SUBAGENT_MODEL` стоит в порядке выбора раньше модели лида. Если сессия принудительно задаёт одну модель всем субагентам (она старше хука) — мод это обнаруживает по `usage.model` первого запроса исполнителя, не совпавшему с выставленной моделью, и говорит об этом лиду и владельцу.
- **Окно council** = весь ход главного, начатый `prompt.submit` с `command` ∈ {`council`, `planning-council`, `observation-council`}, до `turn.complete` главного, включая все циклы инструментов. Три скила не запускаются форком (во frontmatter нет `context: fork`, проверено), значит `prompt.submit` с `command` приходит.
- **Таблица цен** — ключ по семейству и версии, `usage.model` (полный id) сводится к ключу по префиксу (`claude-opus-5-5…` → opus 5.5). Цены, которых нет в источнике (чтение кеша Haiku 5.5), берутся из актуальной документации при реализации; пока не найдены — по цене входа этой модели (переоценка, а не недооценка).

## 8. Вне объёма

- Отдельные сессии и межсессионная связь (D2).
- Автоматическая классификация задач модом — суждение остаётся за лидом.

- Числа лимитов — после недели наблюдения отдельным решением владельца.

## 9. Риски

| Риск | Что делаем |
|---|---|
| Делегирование мелочи дороже, чем сделать самому (задание + запуск субагента + проверка) | порог «делать самому» в рубрике; журнал недели покажет реальные накладные |
| Пересказ Haiku теряет деталь → переделка | цитаты `file:line` в шаблоне задания; приёмка лидом |
| Пушевая сводка сама перечитывается кешем на каждом ходу | только изменения, потолок 600 символов, слияние |
| Исполнитель не в фоне → лид ждёт, тревогу некому получить | п.6 рубрики; сводка помечает такой спавн |
| Fable думает минутами → ложная тревога | порог тишины 15 мин; короткое молчание лечит движок |
| `CLAUDE_CODE_SUBAGENT_MODEL=sonnet` отправит на Sonnet и агента, которому нужен Opus, если лид забыл модель | в рубрике: Opus для проверки и мышления — всегда явно; у проверяющих агентов `model: opus` во frontmatter |
| Кто-то включит `/advisor` — Sonnet-исполнители начнут звать советчика сами | D15 в рубрике; мод видит вызовы советчика в `serverToolUses` результата `turn.step` и пишет их в сводку (отказать не может) |
| `omitClaudeMd` у `scout` лишает его правил CLAUDE.md | `scout` только читает; правила про запись ему не нужны |
| Лид обходит council ручным спавном четырёх агентов | маркер `COUNCIL MISSION`; без маркера — остаётся правило рубрики (детерминированно не ловится) |
| `model:`/`maxTurns:` во frontmatter агентов движка ломают установку для Codex/Gemini | проверить установщик движка на этих полях до правки агентов |
| Цены устаревают | таблица с датой источника; неизвестная модель считается по Fable и помечается |
| Форки идут на модели лида | правило рубрики; пометка в сводке |
